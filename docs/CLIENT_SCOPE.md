# Scope: the proposal, line by line

Each promise in `docs/PROPOSAL.md`, and the feature that meets it. "Status" is filled in from `docs/BUILD_LEDGER.md` as work is verified.

| The proposal says | In OfficeProof Lab |
| --- | --- |
| "upload generated Office files" | Upload `.xlsx`, `.docx` or `.pptx` to a test case in the app (up to 4 MB). Files are checked by content, not by name. |
| "or connect a document-generation workflow" | The `officeproof` command-line tool and a GitHub Action run the same checks in a pipeline, and can send each run to the app with a project token. |
| "a readable test report" | Every run has a report: verdict, counts, each check with pass or fail, and every finding with where it is and what was expected. |
| "Check spreadsheet formulas" | Every formula is recalculated with Univer's formula engine and compared with the value stored in the file. Formula errors, references to missing sheets, circular references, formulas over empty cells and formulas that break their neighbours' pattern are reported. |
| "expected totals" | Total rows are checked against the rows above them. Test cases can state expected values, sums and ranges. |
| "missing or inconsistent data" | Blank cells inside tables, numbers stored as text, mixed types in a column, duplicate or blank headers. |
| "Compare generated documents and slides against approved reference examples" | A test case can hold an approved reference file. Headings, tables, page setup and fonts (documents), and slide count, size, titles, layouts and fonts (slides) are compared with it. Spreadsheets are compared too: sheets, headers and where formulas should be. |
| "Inspect flagged cells, pages or slides" | The file opens in Univer Sheets, Univer Docs or Univer Slides with flagged places highlighted. Clicking a finding goes to its cell, paragraph or slide. |
| "rerun tests after a fix" | Upload the fixed file to the same test case: the new run shows what was fixed, what is still failing and what is new. In a spreadsheet you can also edit a cell in Univer and rerun the checks on the edited workbook before regenerating. |
| "Export a verification report" | Markdown, HTML, JSON and JUnit XML. |
| "run core checks automatically in CI" | `officeproof check` exits non-zero on confirmed failures and writes JUnit and Markdown. `action.yml` and a sample workflow are in the repository. |
| "deterministic, reproducible checks" | Confirmed findings depend only on the file, the reference and the rules. The engine version is recorded on every run. |
| "Visual comparison and AI-assisted quality findings would be labelled separately from confirmed test failures" | Three labels: Confirmed, Visual and AI-assisted. Only confirmed failures change the verdict or the CI exit code. |
| "Sheets APIs and formula capabilities for workbook inspection" | Univer's formula engine (recalculation, formula parsing) and Univer Sheets. |
| "document and slide rendering/editing components for review" | Univer Docs and Univer Slides. |
| "Where licensed and supported, headless SDK operations could run tests without opening the full editor" | The open-source Univer packages run headless in Node: the CLI and the server recalculate workbooks with no editor. |
| "test cases, comparison rules, CI integrations and a developer-facing results dashboard" | Projects, test cases with rules and references, the CLI and Action, and a dashboard of runs. |
| "complementing rather than duplicating Univer's existing verification features" | OfficeProof Lab tests files produced outside Univer; it does not replace Univer's own data validation or formula error display. |
| "a working testing tool, a public GitHub repository, reproducible sample test cases, integration documentation" | The app, this repository, `samples/` (generated by `npm run samples`), and `docs/INTEGRATION.md`. |
| "Part of the toolkit could be published as a reusable open-source Univer integration" | `lib/engine` is self-contained (no app code) so it can be published as a package. Not yet published. |

## Status (9 November 2026)
Every row above is built and was exercised in a real browser or from the command line; the evidence is in `docs/BUILD_LEDGER.md` (M-002, M-003). The GitHub Action has run on GitHub (M-004). Two things are not yet verified end to end:
- AI-assisted observations against the live Ling 3.2 Flash service (tested with a stand-in server only).
- Accounts and runs on the hosted deployment. The Vercel build passes and the landing page is live, but the project has no database until the owner sets `DATABASE_URL`.

## Not in this release
- Importing files into Univer with Univer's own exchange service (a Pro, server-side feature). OfficeProof Lab reads the Office files itself and builds Univer data from them.
- Pixel-level visual comparison. The visual label covers layout geometry and estimates.
- Legacy formats (`.xls`, `.doc`, `.ppt`), macros, charts and pivot tables.
